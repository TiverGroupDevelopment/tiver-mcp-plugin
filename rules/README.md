# Правила моделирования семейств по проектам

Здесь лежат профили правил: у каждого проекта свои требования к семействам (параметры, категории, вложенность, ориентация). Профиль — папка с тремя файлами:

```
rules/
├── README.md              этот файл
├── _шаблон/               заготовка профиля для нового проекта
└── <Проект>/
    ├── profile.json       машинная часть: ФОП, обязательные параметры, проверки и пороги
    ├── ПРАВИЛА.md         правила для человека и агента: что делать, как, исключения
    └── ФОП….txt           файл общих параметров проекта
```

Профили:

- [Альтерпласт](Альтерпласт/ПРАВИЛА.md) (`alterplast`) — арматура и проходные соединительные детали (муфты, краны, штуцеры).

## Главное: правила подключаются по запросу

Профиль **не применяется по умолчанию**. Команды моделирования (`new_family`, `create_family_*`, …) правил не знают и работают одинаково для любого проекта. Профиль включается только тогда, когда пользователь явно называет проект («делаем для Альтерпласт») или профиль. Без этого агент моделирует по общим возможностям команд и требованиям конкретного запроса.

Так правила одного проекта не попадают в другой, а новые проекты добавляются папкой, без правки кода.

## Как агент работает с профилем

| Шаг | Инструмент | Что даёт |
|---|---|---|
| Какие профили есть | `list_family_rule_profiles` | имя, область, условие применения |
| Перед моделированием | `get_family_rules profile: "<id>"` | текст правил, соглашения, путь к ФОП, обязательные параметры с GUID |
| Во время работы | обычные команды семейств | параметры берутся из ответа `get_family_rules` (ФОП → `add_family_shared_parameters`, категория → `set_family_properties`, …) |
| После моделирования | `check_family_rules profile: "<id>"` | `pass` / `warn` / `fail` по каждому автоматическому правилу и список правил для ручной проверки |
| Для инспектора | `create_family_inspection_copy` | копия семейства с габаритными размерами |

`check_family_rules` проверяет текущее семейство (сессию, активный документ, `familyName` из проекта) или файл по `path`. Только читает.

## profile.json

```jsonc
{
  "id": "alterplast",                 // короткий ключ: get_family_rules profile: "alterplast"
  "name": "Альтерпласт",
  "version": "1.0",
  "scope": "…",                       // к каким семействам относится
  "activation": "…",                  // когда применять (по умолчанию — никогда)
  "revitVersion": "2019",
  "sharedParameterFile": "ФОП2019.txt", // путь относительно папки профиля
  "rulesFile": "ПРАВИЛА.md",
  "manualRules": [{ "rule": "ALT-08", "title": "…" }],   // что проверяется вручную
  "conventions": { … },               // соглашения для агента: категории, ключ таблицы, фиксированные значения
  "checks": { … }                     // автоматические проверки, см. ниже
}
```

### Проверки (`checks`)

Каждая проверка — универсальная функция команды `check_family_rules`. Профиль включает её ключом и задаёт пороги, а `rule` связывает с номером правила в `ПРАВИЛА.md`. Проверки, которых нет в профиле, не выполняются. GUID обязательных параметров сервер берёт из ФОП профиля сам.

| Ключ | Что проверяет | Настройки |
|---|---|---|
| `category` | категория семейства | `allowed`: список `OST_…` |
| `requiredParameters` | общие параметры есть, GUID совпадает с ФОП, тип/экземпляр | `parameters`: `[{name, instance?}]` |
| `materialParameter` | материал всех твёрдых форм и вложенных связан с параметром | `name` |
| `lookupTable` | есть таблица выбора и формулы `size_lookup`, мало типов | `maxTypes` |
| `nesting` | глубина вложенности и число вложенных экземпляров | `maxDepth`, `maxCount` |
| `nestedShared` | у вложенных снята галочка «Общий» | — |
| `connectorSystem` | классификация системы трубных коннекторов | `pipe` (например `Fitting`) |
| `connectorsLinked` | коннекторы связаны попарно | — |
| `connectorOrientation` | ось Y коннекторов направлена вверх | `up` (по умолчанию `[0,0,1]`) |
| `singleGeometry` | число форм и запрещённая геометрия | `maxForms`, `forbid` |
| `labelsOnPlanes` | параметры размеров на опорных плоскостях, а не на геометрии | `allowGeometryLabels`: части имён-исключений |
| `origin` | центр габаритов в начале координат | `toleranceMm`, `axes` |
| `referencePlanes` | созданные опорные плоскости не длиннее геометрии | `maxLengthFactor`, `ignoreTemplatePlanes` |

Новая проверка добавляется в `FamilyRuleChecker.cs` (`familycommandset/Utils/FamilyEditor/`) под новым ключом и включается в профилях, которым она нужна.

## Новый проект

1. Скопировать `_шаблон` в `rules/<Проект>/`, положить ФОП проекта.
2. Заполнить `profile.json`: id, область, условие применения, обязательные параметры, включить нужные проверки.
3. Описать правила в `ПРАВИЛА.md`: номер, суть, как делать (какими командами), как проверять, исключения.
4. Проверить на эталонном семействе: `check_family_rules profile: "<id>" path: "<эталон.rfa>"` — эталон должен проходить.
